1 项目总览

dsh-memory-hub 是 DeepSeek Harness（dsh）官方生态的本地优先、事件驱动跨会话记忆插件：自动捕获会话中的偏好与工具执行结论，并以 4 个 Agent 可调用工具（memory_store / memory_recall / memory_forget / memory_status）提供显式记忆能力。核心立场：纯函数零外部依赖（仅 node 内置模块）、本地 JSONL 持久化、先落盘后入内存、可复算离线评估。

301-360 collectFuzzyTerms（A1）：英文纯字母词（≥4 字符）生成编辑距离 ≤1 变体（删除/相邻交换/替换/插入），过滤停止词与词典外词；editDistance（滚动数组 O(min(m,n)) 空间，4 处断言附算法不变式证明——0.7.0 U7 后 src 仅剩的断言）。

7.3 关键机制要点（读码归纳）

  • BM25 公式：Σ tf·(k1+1)/(tf + k1·(1 − b + b·len/avgdl)) × log(1 + (N − df + 0.5)/(df + 0.5))，k1=1.2 / b=0.75；词频饱和 + 长度归一化解救精炼短记忆（bench：cosine top@1 0% → BM25 100%）。
  • A1 容错：编辑距离 ≤1 变体（Damerau-Levenshtein 四类单编辑）只在精确零命中时以 0.5 折扣兜底，绝不干扰精确排序。
  • A2 语义：英文 3-gram（带 ^/$ 边界）特征空间 + k=16 FNV-1a MinHash 签名；评分用精确覆盖率 |Q∩D|/|Q| ≥0.45（零误差规避小特征集 MinHash 方差）以 0.3 权重兜底；0.9.0 使签名成为真实候选预筛（大查询先 O(K) 剪枝）。
  • A3 价值：instruction 1.25 > decision 1.15 > preference 1.05 > fact 1.0 > generic 0.95，× explicit 1.1；Record 全键编译期拦截漂移。
  • A4 热度：heat = 1 + 0.1·log1p(accessCount)·exp(−Δ/halfLife)，Ebbinghaus 指数冷却/命中复活闭环；0.9.0 插件默认关闭评分衰减（recallDecayHalfLifeDays=0，与 ttlDays=0「永不过期」哲学对齐，60 天记忆真正可召回）。
  • 两级去重：批内 batchSeen（瞬时）+ 库内窗口 isDuplicate（24h，内容哈希精确短路 + 长度窗口预筛 + 0.92 编辑距离阈值）。
  • 写一致性：全部写路径先落盘后入内存，崩溃/失败零残留；删除走 tombstone 逻辑删，重开不加载。
  • 隐私：NFKC 归一化敏感过滤前置（全角 `ｐａｓｓｗｏｒｄ` 不可绕过）；文件 0600 首写生效、新建目录 0700、既有共享目录不被动；显式记忆同样拒绝敏感明文（SENSITIVE_CONTENT）。

8 疑点与观察（遍历后的独立思考）

# 位置 疑点 / 观察 性质
1 eval G5 参数网格 b=0.5 全组合 recall@1 塌缩为 0、其余组合全 1.0——网格实际只有「b 在不在 0.75」两个结论，27 组网格区分度低；门限「默认不劣于任何组合」对 b 之外的 k1/半衰期几乎无压力，敏感性分析表面化。 方法学观察
2 G6 真实数据门 24 个查询由作者挑选、语义锚由作者标注（API 专名即锚），验证更接近「锚点命中率」而非「用户在自然语言下的真实提问」；recall@1 0.79 的含金量取决于锚的客观性。语料同作者维护，存在「语料-锚-查询」三方同源的自证明风险（虽有 SHA 固化防漂移）。 方法学观察
3 engine.ts MinHash A2 评分用精确覆盖率而非 MinHash 估计（正确取舍），MinHash 仅在大查询预筛时生效（特征集 >16）；但 0.9.0 预筛阈值 = 0.45×2/3 = 0.30，为保守下界——若真实覆盖率在 0.30-0.45 之间被预筛剪掉，理论上会漏掉本可 0.3 权重兜底的候选（文档称「评分语义不变」，实为近似：被剪文档不会进入精确评分）。 潜在语义边界
4 index.ts 捕获模式 assistant/message 在 balanced 下不产候选（仅 aggressive 摘要），而 tools/result 在 balanced 下提取事实——「工具结果类事实」与「助手结论」分属两条路径，captureMode 语义在 README 与代码间需要细读才一致。 文档-代码对齐观察
5 store.ts 快照零拷贝 list() 返回共享引用（0.9.0 O 项）——接口注释要求调用方不得修改；但 MemoryStore 接口对自定义实现无强制约束，若第三方实现返回副本则与引擎「替换数组」假设存在隐性契约依赖。 接口隐含契约
6 index.ts 背压 容量 256 的 FIFO 丢弃「最早期」任务——事件洪水时最新事件优先，与「越新越重要」的假设一致，但与「历史着重重放导入」场景（大量 importSources 启动导入）是否会挤占事件队列需实测；启动导入不走该队列（直接 importAll），无竞态。 已核对无竞态
7 导入 vs 自动捕获去重 importer 幂等仅对 imp- id 生效；同一文本若先被自动捕获（randomUUID 后缀 id）再被 planImport 导入，会生成两条不同 id 的记忆（内容相同）——isDuplicate 是召回侧/捕获侧窗口去重，不覆盖导入路径，理论上可产生近重复对（召回时 BM25 会同时命中）。 潜在重复路径
8 0.10.0 断言「325 项」 README/CHANGELOG/ARCHITECTURE 均写明 325 项 vs 版本报告 0.9.0「324 + G6 真实数据门」——加 1 项 G6 用例的一致性可复核，但 G6 实际由 lib 运行器按场景断言，实际计数以 vitest 运行为准。 一致性核验项
9 依赖方向 importer.ts 依赖 capture.ts 的 kind 信号词——导入与实时捕获共享推断词面，0.9.0 后 strength 词表单源化使二者语义联动；若未来调整捕获词表，导入 kind 推断会同步漂移（当前为特性，非缺陷）。 耦合观察
10 评估可复算域 eval 与 bench 均固定 seed + 纯函数，但 G6 依赖磁盘上 3 个语料文件（SHA 固化）与 ImportPlan 的稳定切块——语料字节变化会触发门禁红（有守卫），属预期行为；bench 不进 CI 是设计决策（环境抖动误报）。 设计决策确认
