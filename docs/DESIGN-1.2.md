# DESIGN-1.2：推理升维——激活扩散第五召回线与全链路召回溯源

> 版本 1.2.0（2026-10-30）。前置：DESIGN-1.0（取代协议/融合检索）、DESIGN-1.1（蒸馏/巩固/图谱/矛盾）。
> 本篇回答一个问题：**当记忆已经「记得住、分得清、忘得掉」，下一步的维度跃迁是什么？**
> 答案：从「检索记忆」升维到「基于记忆推理」，并让每一次召回**可解释**。

## 0. 动机：检索的极限

1.1.x 的四条召回线（BM25 精确 / 编辑距离容错 / MinHash 语义 / 图谱邻域）有一个共同的形态学局限：
它们都只回答「**哪些记忆与查询相似**」。但智能体真正需要的第三种能力是——

> 「我知道 A 使用 B，也知道 B 依赖 C；用户问 C 的上游，我能不能**推出** A？」

这是**多跳推理**（multi-hop inference），不是相似度。图谱线（邻域扩展求和）虽有 hop 概念，
但它只做拓扑传播，不保留路径、不区分「直达」与「经中介」的证据强度差异、无法回放推理依据。
第二个局限是**黑盒**：召回结果只有分数，智能体（和用户）无法知道「为什么是这条」——
在记忆影响决策的场景里，不可解释的召回不可信任。

## 1. 模块 E：激活扩散推理线（第五召回线）

### 1.1 认知科学根基

Spreading Activation（Collins & Loftus 1975; Anderson ACT-R）：概念作为节点存储，
检索时激活从源节点沿语义边扩散、随距离衰减——人类记忆的联想检索模型。工程化映射：

| 认知模型 | 本实现                                                                          |
| -------- | ------------------------------------------------------------------------------- |
| 激活源   | 查询实体（`queryEntities` 问句实体 + `alignByTokens` 对齐层，与图谱线同源种子） |
| 扩散     | 沿 `activeOutEdges`（asOf 时刻活跃出边）逐跳扩展                                |
| 衰减     | 每跳 ×`INFER_HOP_DECAY`(0.5)，每边 ×`confidence`（关系词置信度）                |
| 激活阈限 | 波束宽度（beam=16）截断低激活 frontier                                          |
| 提取     | 每个终结实体保留**最优路径**（最高链强度，并列按路径字典序）                    |

### 1.2 与图谱线（第四线）的本质差异

| 维度       | 图谱线（1.1.0）                | 推理线（1.2.0）                                        |
| ---------- | ------------------------------ | ------------------------------------------------------ |
| 语义       | 邻域拓扑求和（「周围有什么」） | 路径证据推理（「怎么到达的」）                         |
| 路径       | 无（只有实体分）               | `InferChain.path` 完整可回放（A—使用→B—依赖→C）        |
| 多路径     | 拓扑叠加                       | 最优路径（∏confidence × hop 衰减 × 最旧边保守时效）    |
| 时效       | currentness（条目年龄）        | 链上**最旧边**年龄约束（任一环节陈旧则整链降权）       |
| 时间正确性 | isEdgeInvalidAt 过滤           | 同一谓词（`activeOutEdges`），推理**不能穿越失效关系** |

### 1.3 确定性与有界性（硬约束）

- **确定性**：frontier 排序（激活降序 → 实体字典序 → 路径序键）、出边排序（target/relation 字典序）、
  并列链按路径字典序保留较小者——**与实体插入顺序无关**（G17 乱序构建对拍锁定）；
- **有界性**：每跳波束 ≤16、链数 ≤16、跳数钳制 1..3——hub 实体（度数数百）扇出不可引爆复杂度；
- **零依赖纯函数**：`now` 注入可复算，不写存储，图是纯运行时视图。

### 1.4 融合接线

- interpolate：`score += INFER_LINE_WEIGHT(0.25) × 链分 × lineBase`（低于图谱线 0.35——
  推理证据天然弱于邻域直达；排在图谱线之后累加，缺省不执行时与 1.1.1 逐字节一致）；
- RRF：推理分作为**第五条秩**参与 `rrfFuseCandidates`（累加序 rb→rf→rc→rg→ri 固定，
  推理专属候选走补录路径，与图谱补录同 id 时就地合并双线证据）；
- 默认**关闭**（`inferEnabled: false`）：缺省行为与 1.1.1 逐字节零变化（bit-exact 门禁锁定）。

## 2. 模块 F：召回溯源（why）

每一次命中附带 `why: RecallProvenance`：

```ts
{ fusion: 'rrf', lines: [{line: 'bm25', value: 1/62}, {line: 'infer', value: 1/61}], lineBase: 1.0, score: 0.0331 }
```

- **interpolate**：`lines[].value` = 各线**实际加分**的加权项系数（按加分顺序记录）；
- **rrf**：`lines[].value` = 倒数秩贡献 `1/(RRF_K + rank)`——与融合算术**同序同值**，
  `Σvalue × lineBase` 精确等于最终分（逐位一致，非近似）；
- `score` 与 `hit.score` 同源（非重算）；`lineBase` = decay×heat×significance×supersededFactor。

实现纪律：溯源是**纯读侧注记**——所有评分分支的算术路径与累加顺序未动一个字节，
`explain=true` 仅旁路记录各项证据（回归测试锁定「explain 不改变任何 score」与「缺省不产生 why 字段」）。

工具面：`memory_recall(query, {infer, explain})`——`explain=true` 时输出含 why 且渲染追加
`（溯源: rrf ← bm25=0.0161 + infer=0.0164）`一行；缺省输出形状与 1.1.1 完全一致。

## 3. 配置面

| 键             | 默认    | 语义                                                              |
| -------------- | ------- | ----------------------------------------------------------------- |
| `inferEnabled` | `false` | 推理线总开关（与 `graphEnabled` 同形态：配置默认 + 参数逐次覆盖） |
| `inferMaxHops` | `2`     | 链最大跳数（Schema 与 normalizeConfig 双层钳制 1..3）             |
| `inferWeight`  | `0.25`  | interpolate 融合权重（仅 RecallOptions，评估调参用）              |

图运行时构建条件从 `graphEnabled` 放宽为 `graphEnabled || inferEnabled`（推理线沿图谱出边扩散，
无图不推理）；种子识别复用图谱线同一套（问句实体 + token 对齐），两线对同一查询的实体理解一致。

## 4. 验收门限

- **单测（test/memory/infer.test.ts，17 项）**：链语义（两跳/折扣/最优路径/种子排除）、
  确定性（重复调用 + 乱序构建）、asOf 正确性（失效不可穿越 + reassertedAt 复活 + 历史回放）、
  有界性（maxChains 截断 + 波束覆盖面）、引擎集成（interpolate 兜底召回 / RRF 第五秩 /
  inferMaxHops 钳制 / 缺省逐字节零回归）、溯源契约（同源分 / RRF 精确等式 / 缺省无 why）、
  工具面（参数 / 渲染 / metrics.inferHits / 缺省形状）；
- **G17（真实规模推理）**：3333 条真实文档语料——链确定性、跳数/链数/分数有界、
  终结实体反查非空、1 跳终结实体 ⊆ 图谱线 1 跳邻域（两线同源边视图交叉验证）、
  乱序构建逐字节一致、推理线计分非空；
- **G18（溯源契约）**：真实语料召回全命中 why 非空、fusion/score/lineBase 契约成立、
  图谱/推理线真实参与融合、同查询重复调用逐字节一致（含 why）；
- **bit-exact**：`inferEnabled` 缺省/false 时 interpolate+rrf 双模式输出与 1.1.1 逐字节一致。

## 5. 边界与后续

- 英文语料的三元组抽取仍是词表驱动（真实英文文档仅产出片段型实体）——推理线质量受
  抽取召回上界约束，词表扩展属后续独立课题；
- 波束/链数常量（16/16）为保守缺省，`RecallOptions` 已预留注入位供评估网格调参；
- 路径回放到工具输出（`hits[].why` 携带链证据）是自然的下一步——当前链在引擎内部
  聚合为线分，`explain` 已把线的贡献暴露，链的逐步回放待用户侧验证价值后接入。
