# DESIGN-1.3：时空完备——情景回放（episodic replay）与推理证据链

## 0. 动机：asOf 的半截实现

1.1.0 的 `memory_recall asOf` 参数只回放了**图谱时间线**（被取代边失效）与**评分时钟**——
语料本身仍是当前快照：T 时刻之后新写的条目照常参与召回、T 之后改写的内容以新版出现、
T 之前已删除的条目永久缺席。「回到过去问记忆」这个承诺只兑现了一半。

1.3.0 把另一半补上，并把 1.2.0 计算出来却始终藏在引擎内部的推理链（`InferChain.path`）
暴露到工具面。两个模块合成一个主题：**时空完备**——召回不仅可解释（为什么命中），
而且可回溯（当时的记忆库是什么状态、凭什么推理）。

## 1. 模块 G：情景回放（episodic replay）

### 1.1 核心机制：写入日志的纯函数回放

JSONL 存储是 append-only 事件日志（条目快照行 + tombstone 行），天然携带完整历史。
`replayAsOf(raw, asOf)`（`store.ts`，纯函数、单遍、确定性）按**文件序**回放得到
asOf 时刻的精确知识状态：

- **行的写入时刻**由写入协议锚定（都是既有代码的既定行为，非新约束）：
  - 内容/取代/矛盾写入：`updatedAt = 写入时刻`，access 字段原样保留；
  - 热度回写（`bumped`）：`updatedAt` 原样保留，`lastAccessAt = 写入时刻`；
  - 故 `写入时刻 ≡ max(updatedAt, lastAccessAt ?? -∞)`；
- 条目行：`updatedAt ≤ asOf` 且（无 `lastAccessAt` 或 `lastAccessAt ≤ asOf`）→ 该行是
  id 在 asOf 时刻的状态（后行覆盖前行 = 后写覆盖）；否则整行跳过——同时排除
  「asOf 之后才创建/改写的条目」与「asOf 之后的热度回写」（未来访问不污染过去的热度）；
- tombstone 行（1.3.0 起携带删除时刻 `at`）：`at ≤ asOf` → 已删除；`at > asOf` → 忽略
  （尚未发生）；之后的条目行可复活（文件序天然支持 remove→re-add）；
- 旧格式 tombstone（无 `at`）：删除时刻未知 → 保守视为任何时刻已删除；
- 损坏行：跳过并计数（与加载语义同源）。

回放覆盖**全部认知状态维度**：存在性、内容版本、取代/矛盾标注、访问热度。

### 1.2 图谱的 T 时刻视图：重建而非过滤

运行时 `TemporalGraph` 的 `occurredAt` 是「最近一次触碰该边的写入时刻」——取代标记
回写也会推高它，**不等于**关系发生时刻。因此深回放下对边做 `occurredAt ≤ now` 过滤会
误伤 1.2.0 已锁定的 asOf 语义（T 前已存在、T 后被改写的边被错误隐藏）。

正确做法：`memory_recall asOf` 时用**回放语料全量重建**图视图（`buildGraph(replayAsOf(…))`）。
T 时刻图天然精确：未来条目的边不存在；取代/复活状态即 T 时刻快照（被取代条目回放为
带标记版 → 边失效；未发生取代 → 边活跃）。缺省（无 asOf）沿用运行时图，行为与 1.2.0
逐字节一致。

### 1.3 接线与降级

- `JsonlMemoryStore.listAsOf(asOf)`：每次调用重读磁盘按行回放（只读、不占写链、
  不污染 IndexCache——回放语料直接走 `engine.recall`，不进以当前语料为键的缓存）；
- `MemoryStore.listAsOf?`（可选接口成员）：不支持回放的实现由工具层降级为
  `createdAt ≤ asOf` 过滤（存在性近似，无内容版本回溯——文档化降级）；
- 只读语义：asOf 调用不写热度（1.1.0 已有，保持）；`metrics.asOfRecalls` 观测计数；
  渲染前缀 `[memory recall @<ISO8601>]`（缺省无前缀，形状不变）。

## 2. 模块 H：推理证据链（why.chains）

1.2.0 的 `why` 只说「infer 线贡献了 0.0164」，不说**凭什么**。1.3.0 在 `why` 上追加
可选 `chains`（仅 explain=true 且该命中 infer 线参与融合时）：

- 至多 3 条链，按链强度降序（链集合本身已确定性排序，截断与遍历顺序无关）；
- 每条链 = `{path, terminal, score}`：路径逐边 `{from, relation, to, confidence, occurredAt}`，
  可直接回放「A —使用→ B —依赖→ C」；
- 收集机制与 `rrfFuseCandidates` 的 `ranksOut` 同一模式（纯出参）：`inferLineScores`
  新增 `opts.chainsOut`，评分路径零改动；
- 工具面 schema 遵守 dsh-tools 嵌套对象 `additionalProperties: false` 契约；
  渲染追加 `（推理: A —使用→ B —依赖→ C (0.42)）`（至多 2 条）。

## 4. 边界与后续

- **compact 降级**：compact 清除历史行（被覆盖旧版本与 tombstone），此后深回放退化为
  「最新快照的存在性判定」——被删除条目的最新行同样被清除（存在性仍正确），但内容
  版本与删除时刻不可再回溯。深回放精度以未 compact 的日志为前提（默认阈值
  行数 > 条目×2 且 ≥64 才触发，日常库可长期保持可回放）；
- **运行时图 vs 回放图**：库用户直接持运行时图做深 asOf 时，post-T 断言的两个旧实体间
  新关系可能贡献图/推理分（occurredAt 语义限制，见 §1.2）；生产工具路径无此问题
  （asOf 一律重建回放图）；
- **英文实体抽取**：真实英文语料的图实体仍以碎片为主（G17 以真实抽取输出接地），
  跨语言实体 grounded 抽取是后续独立课题（roadmap）；
- **未来工作**：`memory_status` 的历史统计视图（按 asOf 汇报当时规模）；情景回放结果的
  diff 视图（T1 与 T2 之间记忆库发生了什么）。
