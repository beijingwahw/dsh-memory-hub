# CENTURY-0.4：dsh-memory-hub 世纪级整体升级方案

> 版本：0.4.0 ｜ 状态：✅ 实施完成（2026-10-05：141 测试全绿，lines 93.04 / branches 88.91，超 0.3 基线）｜ 基线：0.3.0（113 测试全绿，lines 91.68 / branches 87.91）

## 1. 升级目标

在 0.2.0 → 0.3.0 两轮世界级进化的基础上，对**整个项目**做一次世纪级整体升级：

1. **检索质量跃升**：把"够用"的 TF·IDF cosine 升级为现代检索基线 **Okapi BM25 智能评分**，叠加查询规范化与停止词处理，让召回排序更符合人类直觉；
2. **存储自愈与迁移闭环**：损坏行隔离留证、compact 后自检、`exportAll` 打通跨设备迁移（与既有 `importAll` 闭环）；
3. **工程护栏不降反升**：全部评分逻辑保持纯函数可复算，测试全绿且数量增加，覆盖率不低于 0.3 基线。

硬约束（贯穿全轮）：4 个工具（memory_store / memory_recall / memory_forget / memory_status）**名称、参数、安装方式不变**；`MemoryEntry` 数据契约不变；zip 沿用 `dsh-memory-hub-0.1.0.zip` 同名重打包，zip 内版本 0.4.0。

## 4. 世纪升级设计（0.4.0）

### A. 检索引擎：BM25 智能评分（`engine.ts`）

**A1. BM25 评分内核**（Lucene 基准参数 k1=1.2, b=0.75）：

```
score(q, d) = Σ_{t ∈ q∩d} IDF(t) × [ tf(t,d) × (k1+1) / ( tf(t,d) + k1 × (1 - b + b × |d| / avgdl) ) ]
IDF(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))   （饱和平滑）
```

- `buildIndex` 增量统计文档长度 `docLen` 与语料平均长度 `avgdl`，`MemoryIndex` 增加 `avgdl` 字段（纯增量，不破坏现有消费者）。
- `queryIndex` 评分公式替换为 `score = bm25 × decay × heat`，**保留**时间衰减、热度、workspace/kind 过滤、limit、token 预算裁剪、空查询短路。
- 全链路（`recall` / `queryIndex` / `IndexCache`）共享同一评分语义，`now` 参数化保证同一基准可复算。

**A2. 查询规范化（NFKC）**：查询词在 tokenize 前统一 `NFKC` 折叠（全角英文 → 半角、异体字符归一），与 capture 侧 `normalizeForMatch` 对齐。中文不受影响。

**A3. 停止词表**：内置英文虚词小表（`the/a/an/is/are/of/to/and/or/for/with/in/on/at/...`），在 `tokenize` 英文词分支过滤；中文 2-gram 不设停止词（双字对本身即含语义，误杀风险高）。`tokenize('Hello World')` 等既有断言不受影响。

**A4. IndexCache 内容指纹失效（性能跃升）**：由于存储热度更新（`accessCount/lastAccessAt`）会触发 `revision++`，高频召回下索引每轮重建。升级：`IndexCache` 记录构建时的**内容指纹**（对 entries 的 `id+content+tags` 做轻量哈希），`revision` 变化但指纹不变（纯热度更新）时**复用旧索引**；指纹变化才重建。既有 `revision` 语义测试（未变复用 / 变化重建 / clear 强制 / 缺省按 0）全部保持。

**A5. 可复算保证**：A1-A4 全部为纯函数 / 纯内存，不引入 IO 与随机性；`npm run bench` 新增 BM25 与 cosine 的**同库对比基准**，量化质量与性能改进。

### B. 存储层：自愈与迁移（`store.ts` / `types.ts`）

**B1. 损坏行隔离留证**：`open` 加载发现损坏行时，将原始行（错误原文）追加写入同目录 `<file>.corrupt` 隔离文件（0600），保留审计证据；主文件不动、跳过计数语义不变（`diagnostics.lines/corrupt` 形状不变，`tools-0.3.test.ts` 断言不受影响）。仅在存在损坏行时触发，零写入路径无副作用。

**B2. compact 自检**：compact 重写完成后重读新文件，校验行数与条目数一致；不一致仅告警（不把成功调用变失败，符合既有 compact 容错哲学），日志暴露风险。

**B3. `exportAll?()` 迁移闭环**：`MemoryStore` 接口新增可选成员 `exportAll?(): Promise<string>`（JSON 数组序列化全部有效条目），`JsonlMemoryStore` 实现（按排序快照导出，0600 语义不变）。与 `importAll` 组成对称闭环：`exportAll → importAll` 跨设备无损迁移。可选成员不破坏既有实现方契约。

### C. 工程护栏（测试 / bench / 文档）

**C1. 测试**：新增覆盖 A1-A4 / B1-B3 的测试（BM25 质量、规范化、停止词、指纹缓存、损坏隔离、compact 自检、exportAll 往返），**总量 ≥ 113，只增不减**；既有 113 用例全部保持全绿（A 组为评分语义升级，逐一核对既有断言在 BM25 下语义等价，见 §5 兼容性论证）。

**C2. 覆盖率**：vitest 阈值维持（lines ≥ 91.68 / branches ≥ 87.91，实际以运行结果为准），新增代码不降低。

**C3. bench**：`recall.bench.ts` 增加 BM25 冷/热查询与构建基准，运行后记录 1K/10K 对比数据到本文档附录。

**C4. 文档**：README（特性/评分说明/配置）、ARCHITECTURE（BM25、指纹缓存、隔离、迁移）、CHANGELOG（0.4.0）同步；新增本方案 `docs/CENTURY-0.4.md`。
