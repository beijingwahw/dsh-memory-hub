# dsh-memory-hub 真实数据接地（0.9.0 → 0.10.0）

> 定位：把离线质量评估从「固定 seed 合成黄金语料自证」升级为**真实数据验证 + 合成语料回归**双轨——
> 用真实、公开、可复算的官方文档语料，经**生产同路径**导入记忆库，以真实问题跑召回质量门。
> 验证的不是"评估套件自洽"，而是**插件对接真实数据后召回质量依然可靠**。
> 版本：0.10.0（G6 真实数据门）｜许可证：MIT｜语料：`eval/realdata/`（随仓库分发，评测不联网）

---

## 1. 为什么需要"接地"（动机）

0.5.0–0.9.0 的 A5 离线评估（G1–G5）以 mulberry32 固定 seed 构造"理想黄金语料"，五门限全绿、recall@1=1.0。这证明**引擎在构造场景上正确**，但存在一个方法论缺口：

> 合成语料 100% 完美 = 自我证明的弱点。真实数据含代码块、多段落、同义表达、切块噪声，
> 第一答命中不可能 100%。**"对接真实数据后依然可靠"必须用真实数据验证，而不是宣传语。**

同时 0.6.0 已提供 `importSources` 真实数据接入（Markdown 文档 / 会话 JSONL → `planImport` → 记忆库），
但此前只有 6 项"真实 README 词可召回"的冒烟测试，没有规模的、可复算的召回质量门。
0.10.0 补上这一环：**G6 真实数据门（real-data grounding gate）**。

## 2. 数据来源与可信度（真实 + 公开 + 固定版本）

| 文件      | 来源                                       | 固定版本     | 快照 URL                                                               | SHA-256                                                            | 字节  |
| --------- | ------------------------------------------ | ------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------ | ----- |
| `path.md` | Node.js 官方 API 文档（`doc/api/path.md`） | **v26.10.0** | https://raw.githubusercontent.com/nodejs/node/v26.10.0/doc/api/path.md | `f6e28a9cefcedcf35cbcf39f46c1da561e2880cfc358251632627b21c58703c6` | 16915 |
| `os.md`   | Node.js 官方 API 文档（`doc/api/os.md`）   | **v26.10.0** | https://raw.githubusercontent.com/nodejs/node/v26.10.0/doc/api/os.md   | `00eafdab442c752c0edcc1375bbe226938efa5cb20670ee64591c4858573ab8d` | 37124 |

**为什么选它：**

- **真实**：Node.js 官方文档是全球最活跃的开源项目文档之一，由真实维护者撰写、真实用户阅读；
- **可信**：官方仓库固定 tag（v26.10.0）快照，SHA-256 固化在 `eval/realdata/MANIFEST.md`；
- **可复算**：语料随仓库分发，评测全程不联网——任何机器、任何时间 `npm run eval` 逐字节同结果；
- **有挑战**：API 文档混合标题块、描述块、代码示例块、跨页交叉引用，是典型"真实记忆库"形态。

> 为什么不是会话 JSONL：仓库无真实会话日志资产，外部无稳定可得的公开 dsh 会话语料；
> 文档语料经 `planImport` 走的是与 `importSources.sessionLogs` **同一条生产导入管线**，
> 验证的真实接入路径（切块 → 推断 → 过滤 → 幂等 → 索引 → 召回）与文档/会话两条入口共享。

## 3. 清洗与接入方式（生产同路径）

真实文档文本**不经过任何评估专用预处理**，直接走生产管线：

```
eval/realdata/path.md + os.md（固定 tag 快照，SHA-256 校验）
  → planImport({ documents })        // src/memory/importer.ts —— 与插件启动 importSources 同路径
      ├─ splitDocument 切块           // 标题/列表/连续段落聚合，索引行跳过
      ├─ kind 推断                    // instruction / preference / generic
      ├─ 敏感过滤（NFKC 归一化）      // 隐私防线零豁免
      ├─ 长短校验（<8 字符丢弃）      // 质量防线零豁免
      └─ 内容哈希幂等 id（imp-…）     // 与既有导入库可合并去重
  → MemoryEntry[]（329 条真实记忆）
  → IndexCache.query（BM25 + A1/A2/A3/A4 全链路）
```

**实测入库分布（0.10.0 冻结快照）**：329 条记忆，kind 分布 generic 320 / preference 4 / instruction 5，
来源全部 `explicit`——与"启动导入真实文档"的生产行为完全一致。

## 4. 查询集与相关标注（真实问句 + 语义锚）

**查询**：24 个真实用户会问的 API 使用问题（英文自然问法），path 12 问 + os 12 问。
示例：

| #   | 查询（真实问句）                                | 语义锚（API 专名/关键短语）                                   |
| --- | ----------------------------------------------- | ------------------------------------------------------------- |
| 1   | What does path.extname return for a given file? | `path.extname`, `extension of the path`                       |
| 8   | What is the path separator on Windows?          | `path.sep`, `separator is a backslash`                        |
| 13  | What does os.cpus return?                       | `os.cpus`, `array of objects representing a logical CPU core` |
| 23  | What does os.loadavg return?                    | `os.loadavg`, `1, 5, and 15 minute load averages`             |

**相关标注 = 语义空间对齐**（0.10.0 设计要点）：以 API 专名 + 高辨识短语为**锚**，导入库中
**含任一锚的全部块**（标题块/描述块/示例块均算）视为相关。

为什么不是"单句对齐"：真实文档 `splitDocument` 切块后，API 标题块（如 `os.uptime()`）
与描述块（如 _Returns the system uptime…_）是**两块记忆**，用户问"os.uptime 返回什么"时
两块都是答案——单句锚定会把标题块误判为 miss，低估真实召回（0.10.0 探针实测：单句锚 recall@1=0.40 →
语义锚 **0.79**，后者才贴近用户感知）。

**完整性守卫**：每个查询的锚必须在导入库中至少命中一条记忆（`relevant.length > 0`），
否则语料漂移/文件丢失直接门禁红——防"语料悄悄空了还全绿"。

## 5. 门限设计与实测对比

### 5.1 门限（0.10.0 冻结，保守且可复算）

| 门限       | 值     | 理由                                                         |
| ---------- | ------ | ------------------------------------------------------------ |
| recall@1   | ≥ 0.75 | 真实问句第一答无 100% 保证（代码块/同义噪声），0.75 留安全垫 |
| recall@3   | ≥ 0.85 | top-3 必须高置信（真实召回下限）                             |
| recall@5   | ≥ 0.95 | top-5 接近全中（真实记忆库可用性底线）                       |
| MRR        | 报告值 | 不设门限，报告呈现                                           |
| 锚点完整性 | 100%   | 每查询 relevant 非空（语料漂移守卫）                         |

### 5.2 实测（0.10.0 `npm run eval`，329 条真实记忆 × 24 查询）

| 指标     | 实测值（G6）  | 门限  | 结果 |
| -------- | ------------- | ----- | ---- |
| recall@1 | **0.7917**    | ≥0.75 | ✅   |
| recall@3 | **0.8750**    | ≥0.85 | ✅   |
| recall@5 | **0.9583**    | ≥0.95 | ✅   |
| MRR      | **0.8542**    | —     | 报告 |
| NDCG@3   | 0.6129        | —     | 报告 |
| NDCG@5   | 0.6719        | —     | 报告 |
| 锚点命中 | 24/24（100%） | =100% | ✅   |

### 5.3 合成语料 vs 真实数据对比（诚实呈现差异）

| 维度     | G1–G5（合成）             | G6（真实）           | 差异解读                                     |
| -------- | ------------------------- | -------------------- | -------------------------------------------- |
| recall@1 | 1.0（G1）/ 0.90 / 0.80    | 0.79                 | 真实数据有等价表达/代码块噪声，第一答非 100% |
| recall@3 | ≥0.98（G1）               | 0.88                 | 真实 top-3 仍高置信                          |
| recall@5 | —（G1 未测）              | 0.96                 | 真实 top-5 接近全中（可用性底线达成）        |
| 查询类型 | 错拼/词根变体（合成构造） | 自然问句（真实措辞） | 互补覆盖：合成测引擎健壮性，真实测对接有效性 |

**结论**：不是"真实数据表现下降"，而是**两种口径互补**——合成语料证明引擎在理想边界内正确，
真实数据证明引擎在真实噪声下依然可用（top-3 ≥ 0.85 是"多数问题能想起"的可靠下限）。
